# 星球防线 / Star Defense

一句话概括：**把《植物大战僵尸》的“布置防线、抵挡虫群”搬到 3D 战场，再把原本悬在地图上方的那只手变成一个真正站在战场里的玩家。**

玩家不再拥有上帝视角，也不能隔空完成所有事情。你要亲自离开基地寻找资源，跑到合适的位置摆下建筑，用镐子完成施工，在防线被撕开时举枪补位，受伤倒地后再从基地重新出发。

联网版本希望继续放大这种手忙脚乱的感觉，最终成为一款 friendslop 式合作塔防：重点不是严谨分工或竞技排名，而是几个人一边沟通、一边犯错、一边勉强把基地救回来。

目前项目仍是单机原型，联网尚未实现。

## 玩法定位

《星球防线》的起点是“3D 版《植物大战僵尸》”，但不是把草坪和植物简单换成立体模型。

《植物大战僵尸》的核心乐趣来自三件事：有限资源、持续推进的敌群，以及不断调整的防线组合。本作保留这套骨架，同时把玩家从观察者变成战场中的一个单位。

| 传统塔防中的概念 | 《星球防线》里的对应设计 |
|---|---|
| 从上方观察整片战场 | 第一人称行动，只能看见自己所在方向的局势 |
| 点击资源并直接放置单位 | 亲自采集金属、能源和晶体，再到现场建造 |
| 植物组成固定防线 | 炮塔、墙体、供电和支援建筑组成基地网络 |
| 敌人沿路线持续推进 | 虫群从基地四周出现，直奔核心并拆除沿路障碍 |
| 铲除植物后重新布阵 | 拆除建筑、返还部分资源并释放容量 |
| 玩家负责全局调度 | 玩家还要射击、施工、维修、赶路和承担受伤风险 |

这个变化带来的不是单纯“多了一把枪”，而是新的决策成本：

- 想扩张，就必须离开安全区去找矿；离基地越远，回防越慢。
- 想让炮塔开火，不能只看造价，还要考虑建筑容量和电力供应。
- 建筑摆下后不会立刻工作，玩家需要继续施工；未完工的工地不会挡住玩家和敌人。
- 枪能救急，但玩家不可能同时守住四个方向。稳定火力仍然来自防线本身。
- 玩家在修墙时就无法采矿，在外采矿时也看不到基地另一侧发生了什么。

所以本作真正想做的是：**把塔防里的布局题，变成一个需要人在现场执行的协作题。**

## 一局游戏怎么进行

当前默认对局约 16 分 30 秒，目标是保护基地核心，撑过 Boss 与最后的撤离窗口。

1. **登陆与准备**：玩家在基地附近出生，利用初始资源补上第一批防御。此时最重要的是决定先守哪个方向，而不是平均铺满整圈。

2. **外出采集**：地图上分布着金属、能源和晶体。基础资源靠近基地，晶体主要位于外圈。想造更强的建筑，就必须冒险走得更远。

3. **施工与布防**：玩家切换到建造模式，选择建筑并放置蓝色虚影。建筑落地后仍处于施工状态，需要用镐子继续完成；建成前不会形成实体路障。

4. **虫群来袭**：开局约一分钟后，四个方向的刷怪点开始按各自节奏出兵。普通敌人优先攻击基地；如果已建成的墙或建筑挡住去路，它们会先停下来拆除障碍。

5. **修补缺口**：玩家需要在射击、维修、拆除重建和继续采集之间切换。自爆、钻地、远程狙击和建筑干扰会分别针对不同防守习惯。

6. **Boss 与撤离**：对局后段出现行星巨兽。基地核心存活到撤离结束即胜利；核心被摧毁则立即失败。

核心循环可以压缩成一句话：

> 出门找资源 → 回基地施工 → 防线自动接敌 → 玩家处理意外 → 用新资源调整下一轮防线

## 玩家在防线里扮演什么角色

玩家不是一座移动炮塔，也不是传统塔防中的万能鼠标。

更合适的定位是“现场工程师”：

- **采集者**：决定是否为高级资源冒险离开基地。
- **建造者**：选择防线形状，并亲自完成施工。
- **救火队员**：赶往最危险的方向，用枪暂时堵住缺口。
- **维护者**：维修受损建筑，拆掉错误布局，保证供电与容量不被浪费。
- **风险承担者**：会被敌人追击、狙击和击倒，不可能永远安全地发号施令。

设计上，建筑负责长期收益，玩家负责短期应变。只靠枪会顾不过来，只靠炮塔又处理不了钻地、干扰和防线外的资源需求。

## 联网后的目标：friendslop 式合作

联网不是简单地把 AI 队友换成真人，而是要让“每个人都只能处理局部”成为乐趣来源。

理想中的一局可能是这样：一个人在外圈挖晶体，一个人在北面补墙，一个人在基地里发现电力不够，最后一个人正追着漏进来的自爆虫开枪。大家都知道大致目标，但没人能同时掌握完整战场，于是沟通、误判和临场补救自然发生。

计划中的合作原则：

- **不设死职业**：玩家拿的是同一套基础工具，分工由当前局势自然形成。
- **允许犯错，但不要一错退局**：放错建筑可以拆，玩家倒地可以救，局部失守仍有补救空间。
- **让队友的行为看得见**：施工、搬资源、维修、开火和求救都应该有明确反馈。
- **制造可以讲出来的事故**：有人贪远处晶体、有人忘了发电机、三个人同时去修同一面墙——这些混乱本身就是合作体验的一部分。
- **最终目标始终一致**：所有人的资源、建筑和行动都服务于同一个基地核心，避免合作局变成四个人各玩各的。

当前单机版放置了 3 名 AI 队友，用来维持采集和火力节奏；它们只是联网玩法的临时占位，并不代表最终的合作系统。

## 建筑与敌人

### 建筑

当前有 8 种可建造设施：

| 建筑 | 主要作用 |
|---|---|
| 机枪塔 | 便宜、射速快，处理持续出现的普通敌人 |
| 炮塔 | 射程远、单发伤害高，并带有范围爆炸 |
| 电磁塔 | 近中距离群体伤害，并减慢敌人 |
| 能量墙 | 用容量和资源换取防线纵深，迫使敌人停下拆墙 |
| 发电机 | 提高电力供应，为更多防御和支援建筑供能 |
| 维修站 | 持续消耗能源，自动修复附近建筑 |
| 护盾发生器 | 为范围内建筑提供可恢复的额外护盾 |
| 雷达 | 侦察职能预留；当前主要用于验证建造与资源系统 |

基地有容量上限，建造中的设施也会占用容量。高强度建筑通常还需要更多电力，因此不能只堆最贵的炮塔。

### 敌人

当前敌人围绕“破坏一种防守习惯”来区分：

| 敌人 | 对防线造成的压力 |
|---|---|
| 普通虫 | 正面推进，检验基础火力是否足够 |
| 自爆虫 | 接近后造成范围伤害，惩罚过度密集的建筑群 |
| 挖掘虫 | 从地下绕过常规防线，逼玩家保留核心附近的应急能力 |
| 狙击虫 | 在远处点名玩家，迫使采集者和施工者寻找掩体或主动清除 |
| 干扰虫 | 周期性瘫痪附近建筑，让完整防线暂时失去作用 |
| 搬运虫 | 玩法与模型仍在预留阶段，目前使用占位表现 |
| 行星巨兽 | 对局后段的高血量 Boss；完整阶段机制和演出尚未完成 |

## 当前完成度

已经可以体验的内容：

- 第一人称移动、跳跃、射击、采集、建造、维修和拆除。
- 金属、能源、晶体三种资源，以及建筑容量和供电系统。
- 8 种建筑、多个敌人行为、四方向可配置刷怪点。
- 施工进度、建筑阻挡、敌人遇阻拆建筑、玩家倒地与基地复活。
- 一张带起伏的沙漠星球地图，以及一套卡通低模角色、建筑和虫群资产。
- 从登陆、扩张、防守、Boss 到撤离的完整胜负流程。

还没有完成的内容：

- 真正的多人联网、队友救援和网络状态同步。
- 存档、音效与完整设置菜单。
- 搬运虫的正式玩法和模型。
- Boss 的多阶段机制、敌人特殊动作与完整战斗演出。
- 雷达的侦察界面。
- 雷达、维修站、护盾发生器、发电机仍使用程序化占位造型。

## 操作

| 按键 | 作用 |
|---|---|
| WASD / 鼠标 | 移动 / 转动视角 |
| Shift | 奔跑 |
| Space | 跳跃 |
| 左键 | 使用当前工具：开枪、采集、施工或放置建筑 |
| 右键 | 退出建造模式 / 取消选择 |
| Q | 切换枪与镐子 |
| X | 手持镐子时切换采集 / 建造模式 |
| 1–8 / 鼠标滚轮 | 在建造模式中选择建筑 |

| R | 拆除准星指向的建筑 |
| Esc | 锁定或释放鼠标 |

## 运行工程

需要 **Unity 2022.3.62f3c1（中国区版）**。

`Packages/manifest.json` 依赖 `cn.unity.uos.launcher`，使用国际版 Unity 打开时可能无法正常获取该包。

1. 用 Unity 打开工程。
2. 等待资产生成管线自动执行完毕。
3. 打开 `Assets/StarDefense/Scenes/PlanetDefense_FirstVersion.unity`。
4. 点击 Play。

首次构建记录位于 `Logs/StarDefensePipeline.txt`。

场景由编辑器脚本生成，不要直接在场景文件里做长期修改。需要调整地图、出生点或初始布防时，应修改 `Assets/StarDefense/Scripts/Editor/` 下的构建器并重新运行管线，否则下次重建会覆盖手工改动。

## 工程目录

```text
Assets/StarDefense/
  Scripts/Runtime/      对局、玩家、敌人、建造和 UI
  Scripts/Editor/       资产导入与场景生成管线
  ScriptableObjects/    建筑、敌人、波次和全局数值
  Art/                  模型、贴图、材质、动画和 Prefab
  Scenes/               主场景
  Meshes/               生成的地形网格
.workbuddy/             项目规则、美术契约和协作记录
```

项目采用双工程结构：Unity 运行内容位于本仓库；Blender 源文件和原始美术素材保存在独立素材工程中，不会把 `.blend` 文件提交到 Unity 工程。

更具体的开发约定见：

- `.workbuddy/project-rules/PROJECT_PATHS.md`
- `.workbuddy/project-rules/OBJECT_TAXONOMY.md`
- `.workbuddy/project-rules/ASSET_BACKLOG.md`
- `.workbuddy/skills/star-defense-production/`
- `.workbuddy/skills/star-defense-art-style/`
